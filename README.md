# mdviewer

## npmコマンド

| コマンド | 実体 | 説明 |
|---|---|---|
| `npm run dev` | `electron-vite dev` | 開発起動（ホットリロード対応） |
| `npm run build` | `electron-vite build` | 配布用ビルドを`out/`に生成する |
| `npm run start` | `electron-vite preview` | 再ビルドしてからアプリを起動し、動作確認する（事前に`npm run build`を実行しておく必要はない） |
| `npm run pack` | `electron-vite build && node scripts/pack.mjs` | 再ビルドし、Electron本体を含む配布用ZIP（`release/mdviewer.zip`）を作成する。別PCにNode.jsが入っていなくても、解凍後`mdviewer.bat`をダブルクリックするだけで起動できる |
| `npm run cleanup` | `node scripts/cleanup.mjs` | `out/`・`release/`・`dist/`を削除する |
| `npm test` | `vitest run` | ユニットテストを実行する |
| `npm run typecheck` | `tsc --noEmit -p tsconfig.node.json && tsc --noEmit -p tsconfig.web.json` | 型チェックを実行する |

`build`・`start`・`pack`はいずれも実行のたびに`out/`を自動的にクリーンアップしてから再生成する（Vite標準の`emptyOutDir`挙動）。手動でのクリーンアップが必要な場合は`npm run cleanup`を使う。

配布方針として、electron-builder等によるEXE化・インストーラー作成は行わない。

## フォルダ構成

プロジェクト直下にあるフォルダの位置付けを一覧にする。

| フォルダ | 分類 | 解説 |
|---|---|---|
| `.git` | 恒久 | Gitリポジトリ本体（コミット履歴等）。バージョン管理に必須 |
| `node_modules` | 生成物（再生成可能） | `npm install`の依存パッケージ実体。`.gitignore`対象で、削除しても`npm install`で復元可能 |
| `out` | 一時（生成物） | `electron-vite build`のビルド出力。`.gitignore`対象で、`npm run build`等のたびに再生成される。存在しない時期もある |
| `release` | 一時（生成物） | `npm run pack`が作る配布用フォルダ・ZIP一式。`.gitignore`対象で、`npm run pack`のたびに再生成される。存在しない時期もある |
| `scripts` | 恒久 | `npm run pack`・`npm run cleanup`が呼び出すNode.jsスクリプト（`pack.mjs`・`cleanup.mjs`） |
| `src` | 恒久 | アプリケーション本体のソースコード |

## 開発手順

### 前提条件

- Windows環境であること（開発OSはWindows）
- Node.js（npm同梱）がインストールされていること

### セットアップ

1. リポジトリを取得する。
2. `npm install`を実行する（生成される`node_modules`フォルダについてはフォルダ構成を参照）。

### 開発中の起動

- `npm run dev`を実行すると、ホットリロード対応の開発モードで起動する。編集対象は`src`フォルダ（フォルダ構成を参照）。

### 型チェック・テスト

- `npm run typecheck`で型チェックを実行する。
- `npm test`（`vitest run`）でユニットテストを実行する。テスト対象は`tests/unit`配下（ファイル関連付け、エンコーディング判定、Markdown/HTMLレンダリング、構造化データ、目次生成、タブコンテナ、設定永続化等）。

### ビルドと動作確認

- `npm run build`を実行すると`out`フォルダ（フォルダ構成を参照）に配布用ビルドが生成される。
- `npm run start`で、再ビルドしたうえで動作確認できる。

### 配布用ZIPの作成

- `npm run pack`を実行すると、`scripts`フォルダのスクリプトにより`release`フォルダ（いずれもフォルダ構成を参照）へ配布用ZIPが生成される。
- 不要な生成物は`npm run cleanup`で削除できる。

### コーディング規約・技術方針

- 主な原則: TypeScript固定、React/Vue等のUIフレームワーク不使用、electron-builder等によるEXE化禁止、外部通信禁止、設定永続化はelectron-store使用、等

## 利用方法

mdviewerは、Markdown・JSON・YAML・XML・HTML・PDFファイルを表示できる、Windows向けの単体ファイルビューアです。外部通信を一切行わずローカルで完結し、設定を保存するかどうかも自分で選べます。

### 主な機能

- 対応ファイル形式: Markdown、JSON、YAML、XML、HTML、PDF
- タブ表示で複数のファイルを同時に開ける。
- 見出しから生成される目次（TOC）サイドバー、表示・非表示の切り替え
- ページ内検索（Ctrl+F）
- ダーク/ライトテーマの切り替え（Mermaidダイアグラムの配色も連動）
- 本文表示幅の切り替え（既定は読みやすい幅に制限、ONで最大幅を拡張。PDF表示は対象外）
- Markdown/HTMLタブでの生データ（raw）表示切り替え（タブ内アイコンから、レンダリング表示と元ファイルのテキスト表示を1クリックで切り替え）
- ファイルのドラッグ&ドロップに対応
- ネイティブメニュー（ファイル/編集）から、ファイルを開く操作や各種切り替えを実行できる。
- 直近に開いたフォルダを記憶し、次回「ファイルを開く」ダイアログの初期表示に使う。
- 設定を保存するかどうかを選べる（保存しない場合、PC上に一切のファイルを残さない）。
- 起動時スプラッシュ画面
- 外部通信を行わず、ローカルで完結する。

### 動作環境

- Windows 10 / 11
- インストール作業は不要（Node.js等の追加ソフトも不要）

### インストールと起動方法

配布された`mdviewer.zip`を使い、次の手順で起動する。

1. `mdviewer.zip`を任意のフォルダへ展開する。
2. 展開したフォルダの中にある起動用ファイルをダブルクリックする。
   - `mdviewer.bat`: 通常の起動方法。起動時に黒いコンソール画面が一瞬だけ表示されて消える。
   - `mdviewer-silent.vbs`: コンソール画面の点滅も避けたい場合の起動方法。画面には何も表示されずアプリだけが起動する。

インストーラーは無く、フォルダを展開するだけで利用できる。アプリを終了しても展開したフォルダはそのまま残るため、次回以降も同じ起動用ファイルから起動できる。

### タスクバー・スタートメニューへの登録（ピン留め）

`mdviewer.bat`・`mdviewer-silent.vbs`は、Windowsの仕様上そのままドラッグ&ドロップしてもタスクバーやスタートにピン留めできない。ピン留めするには、ショートカットを作成しリンク先を書き換える必要がある。

1. 登録したいファイル（`mdviewer.bat`または`mdviewer-silent.vbs`）を右クリック→「ショートカットの作成」を選ぶ。
2. 作成されたショートカットを右クリック→「プロパティ」を開く。
3. 「ショートカット」タブの「リンク先」の先頭に、以下を書き加える（間には半角スペースを1つ入れる）。
   - `mdviewer.bat`の場合: `cmd /c "C:\展開先パス\mdviewer.bat"`
   - `mdviewer-silent.vbs`の場合: `wscript.exe "C:\展開先パス\mdviewer-silent.vbs"`
4. （任意）そのままでは実行元（cmd.exe / wscript.exe）のアイコンになるため、変更したい場合は「アイコンの変更」から選び直す。
5. 「OK」で閉じたのち、ショートカットを右クリックし「タスクバーにピン留めする」または「スタートにピン留めする」を選ぶ。

注意点:

- ショートカット作成後に元の`mdviewer.bat`・`mdviewer-silent.vbs`（展開したフォルダ自体）を移動・リネームすると、ピン留めしたショートカットが起動できなくなる。
- ピン留めが完了すれば、手順1で作成したショートカットファイル自体は削除してよい。

### 使い方

#### ファイルを開く

- メニュー「ファイル」→「ファイルを開く...」（Ctrl+O）から、対応ファイルを選択する。
- 対応ファイルをウィンドウへドラッグ&ドロップする。
- 同じファイルを再度開こうとした場合は、新規タブを作らず既存タブにフォーカスする。

#### タブの操作

- ファイルを開くたびに新規タブとして追加される。
- 各タブの×ボタンでタブを閉じられる。
- 最後の1タブを閉じるとウィンドウごと閉じる。

#### 目次（TOC）の表示・非表示

- 見出しのある文書では、目次（TOC）サイドバーが自動的に表示される。
- メニュー「編集」→「目次を隠す」で表示・非表示を切り替えられる。

#### ページ内検索

- Ctrl+Fで検索バーを開き、表示中の文書内を検索できる。

#### テーマ（ライト/ダーク）の切り替え

- メニュー「編集」→「ダークテーマ」で切り替えられる。
- Mermaidダイアグラムの配色もテーマに連動して切り替わる。

#### 本文表示幅の切り替え

- メニュー「編集」→「ウィンドウ幅に追随」で、本文の最大表示幅を切り替えられる。
- OFF（既定）: 読みやすさを優先し、Markdown/HTML文書は860px、JSON/YAML/XML等の構造化データ表示は960pxを上限に表示する。
- ON: 上限を1200pxまで拡張する（ウィンドウ幅そのものに際限なく追随するわけではなく、上限値が広がるのみ）。
- PDF表示には適用されない。

#### raw表示（生データ表示）の切り替え

- Markdown・HTMLタブでは、タブ内のアイコン（`</>`⇔`●`）をクリックすると、レンダリング表示と生データ表示（元ファイルのテキストをそのまま等幅フォントで表示）を切り替えられる。
- Tabキーでアイコンへフォーカスし、Enter/Spaceキーでも切り替えられる。
- 表示モードはタブごとに独立して保持され、設定として保存されない（タブを閉じると状態は消える）。
- JSON/YAML/XML・PDFタブには本機能は表示されない。

#### 設定の保存有無について

- メニュー「編集」→「設定を保存」のチェックで、設定（テーマ・目次表示・直近フォルダ等）を保存するかどうかを選べる。
- ONの場合: `%APPDATA%\mdviewer\config.json` へ保存され、次回起動時に復元される。
- OFFの場合: 保存先ファイルは作成・保持されず、アプリ終了とともに設定は既定値に戻る。
